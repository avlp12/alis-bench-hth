공정성 프로토콜

best-vs-best — 조건을 맞추는 게 아니라 공개한다

각 모델을 천장까지 끌어올린 뒤 붙인다. 객관성의 앵커는 조건 통일이 아니라 과제·채점·심사의 불변 + 모든 설정의 공개다.

각자 최적 양자화

레시피를 맞추지 않는다 — 각 모델은 자기 팀이 최적화한 빌드로. 대신 모델별 KL(자기 8-bit ‖ 빌드)을 공개해 “그 빌드가 치른 양자화 비용”을 드러낸다(정규화 아님).

각자 최고 설정 + 비용 원장

thinking 최대, 권장 샘플링, 최적 프롬프트 — 천장까지. 단 결과 생성 전에 설정·빌드·런타임 커밋을 동결 기록하고, 실제 소비된 completion/reasoning 토큰을 판정 옆에 병기한다. dirty 트리는 “재현 불가”로 표시.

과제·채점은 고정

같은 문항, 같은 정답 추출·규칙·실행 채점. 여기가 객관성의 앵커 — 모델별로 바뀌면 안 되는 유일한 축.

각자의 채팅 템플릿

공정 = 두 모델이 각자 자기 템플릿·시스템 프롬프트를 쓴다. 한쪽 걸 강요하면 그게 불공정. sanity_probe.py로 검증.

중립 심사 + 위치 디바이어스

개방형은 제3의 심사자, A/B 순서를 뒤집어 양쪽 순서 일치만 승리. 위치 편향률도 공개.

자원은 두 번째 축

더 많은 토큰·메모리를 써서 이겼다면 그것도 결과다. chars/s·thinking 토큰·bpw를 역량 옆에 병기 — 승패를 지우지 않되 비용을 보인다.

사전등록(pre-register)

스위트·주지표·승리규칙·peak 설정을 결과 보기 전 해시·타임스탬프하고 Kimi가 공동서명 — 스위트 선택이 승자를 정하지 못하게.

Fail-closed 무결성

결정적 run-id·필수 셀 매니페스트 — 누락/stale 셀이 있으면 판정 차단. 지표는 metric[filter] 명시 스키마, 판정은 paired 부트스트랩 CI + Holm 다중검정 보정 + 등가 마진 → “판정불가”.

세 트랙으로 나눠 본다

단일 빌드·단일 숫자는 교란 — best-submitted만 “best-vs-best”

양자화 스킬과 베이스 실력이 한 숫자에 섞이면 객관성이 무너진다. 그래서 세 트랙을 분리 보고하고, cross-model KL 랭킹은 금지한다(KL은 각 모델 자기 8-bit 대비 비용일 뿐).

고정밀 베이스

8-bit/bf16 — 양자화 영향 최소 지점. “어느 베이스가 나은가”의 앵커. 두 포트 다 공식 BF16 로짓 대비 패리티 통과 필수.

자원-매칭 양자화

같은 bpw·방법으로 맞춰 양자화 스킬을 통제. “같은 예산에서 어느 양자화가 나은가.”

무제한 best-submitted

각자 최적 빌드 + 최고 설정. 오직 이 트랙만 “best-vs-best”. 비용(bpw·thinking 토큰)을 병기.

결과 자리 — 축만 표시

데이터 없음 · 측정 후 채움
중립 축만 · 경쟁자 색 곡선은 확정 결과 전까지 그리지 않는다

Kimi 핸드오프 — Motif 레시피 참고용

각자 최적 · 강제 매칭 아님

Solar는 Kimi가 자기 최적 방식으로 양자화한다(레시피 강제 아님). 아래는 Motif-3-Beta가 쓴 레시피 — 참고·영감용이며 Kimi가 Solar에 맞춰 능가하면 된다. 비교 파이프라인이 요구하는 건 레시피 일치가 아니라 산출물의 비교가능성: mlx_lm.server 서빙 · 모델별 8-bit ref(KL용) · 자기 채팅 템플릿. 전체 핸드오프 → quant/KIMI_HANDOFF_motif-recipe.md.
